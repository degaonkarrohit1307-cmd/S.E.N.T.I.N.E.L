# ADR-0007: v0.3.4 — Dynamic Plugin Loading

**Status:** Accepted
**Date:** 2026-07-26

## Context
v0.3.1-0.3.3 built discovery, lifecycle state machine, and dependency
ordering, but nothing actually imports plugin code or runs it. v0.3.4
wires these three together into runtime `load_plugin()`/`unload_plugin()`/
`reload_plugin()` on `PluginLoader`.

## Design
- `PluginLoader` now optionally takes a `PluginLifecycleManager` and
  `DependencyGraph` (DI, defaulting to fresh instances) and an optional
  `event_bus`.
- `load_plugin(name)`: finds the manifest via `discover()`, dynamically
  imports the entry point via `importlib.util.spec_from_file_location`
  (file-path based, not package-based -- no sys.path requirement),
  instantiates it, then drives `register_plugin` -> `load_plugin` ->
  `initialize_plugin` -> `start_plugin` on the existing
  `PluginLifecycleManager` unchanged. Updates the runtime registry
  (`_registry`) and `DependencyGraph`. Publishes `PluginLoaded`.
- `unload_plugin(name)`: raises `PluginNotRunningError` if not
  registered; raises `PluginUnloadDeniedError` if
  `graph.get_dependents(name)` intersects currently-loaded plugins;
  otherwise drives `stop_plugin` -> `unload_plugin` on the lifecycle
  manager, removes the node from the graph/registry, evicts the
  dynamically-imported module from `sys.modules`. Publishes
  `PluginUnloaded`.
- `reload_plugin(name)`: requires already-loaded; calls
  `unload_plugin` then `load_plugin`, wrapping any failure in
  `PluginReloadError`. Publishes `PluginReloaded`.
- Duplicate load is checked against the runtime registry directly
  (`InvalidPluginStateError`) rather than relying solely on
  `PluginLifecycleManager.register_plugin`'s reset-on-reregister
  behavior, since that behavior is intentionally idempotent and would
  otherwise silently succeed on a second load.
- Events publish via the same fire-and-forget
  `asyncio.get_running_loop().create_task(...)` pattern already used by
  `ConfigurationManager`, so `PluginLoader` stays sync-callable without
  requiring an event loop to exist.

## Consequences
No existing file's behavior changed except additive constructor
parameters (all optional, defaulted) and new methods on `PluginLoader`;
`exceptions.py` gained three new classes. 12 new tests; 122/122 total
pass.
