# ADR-0003: v0.2.0 Configuration Manager

**Status:** Accepted
**Date:** 2026-07-23

## Context
v0.2 adds centralized configuration (JSON/YAML/env vars, validation,
type-safe access, runtime overrides, hot-reload hook) per the roadmap,
integrating with Kernel, Event Bus, and Security Manager without
breaking any existing public API.

## Decisions

1. **Flat dotted keys internally, regardless of source shape.** JSON/YAML
   nesting (`event_bus: {queue_size: 500}`) and env vars
   (`SENTINEL_EVENT_BUS__QUEUE_SIZE`) both flatten to `event_bus.queue_size`.
   One key format means one merge algorithm, and no consumer needs to
   know which source a value came from.

2. **Precedence: env vars > runtime overrides > YAML > JSON > schema
   defaults.** Standard 12-factor ordering — env vars are the one
   override that requires no file edit, so they must win over anything
   else, including an in-app Settings change.

3. **Fail-closed on validation error, keep last-good config.** `reload()`
   raises on validation failure but leaves `self._values` untouched, so
   a bad edit to `local.yaml` can't silently blank out a running
   system's configuration. A rejected `set_override()` additionally
   rolls back only the offending key rather than leaving the
   `_runtime_overrides` dict permanently poisoned for that key on every
   future, unrelated reload — verified explicitly by
   `test_rejected_override_does_not_poison_later_reloads`.

4. **Both Kernel and Event Bus changes are additive-only.**
   `Kernel(security=...)` and `AsyncEventBus()` still work with zero
   changes to calling code; config is strictly opt-in via a new optional
   parameter. Verified by
   `test_kernel_without_config_still_works_unchanged`.

5. **Hot reload is designed, not wired.** `reload()` and the
   `config.changed` event exist now so no future consumer's shape needs
   to change; an actual file-watcher triggering `reload()` automatically
   is deferred (candidate: v0.3+), keeping this release's surface area
   to exactly what was asked for.

6. **Module Registry integration deferred.** Per-module config sections
   keyed by module id would be natural future work, but no module beyond
   `security_manager` and `demo_echo` yet needs it — added when a real
   module demands it, not speculatively.

## Consequences
- New `PyYAML` dependency (already added to `requirements.txt`).
- `main.py`'s boot sequence gained one more step (build `ConfigurationManager`
  before `SecurityManager`), documented in the updated README.
- No existing test was modified; 19 new tests added, 27/27 passing.
