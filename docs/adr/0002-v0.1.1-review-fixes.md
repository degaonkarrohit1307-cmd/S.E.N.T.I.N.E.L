# ADR-0002: v0.1.1 Code Review — Findings & Fixes

**Status:** Accepted
**Date:** 2026-07-23
**Scope:** Review only. No new features, per instruction.

## Findings

| # | Severity | Finding |
|---|---|---|
| 1 | High | Bare `pytest` invocation failed with `ModuleNotFoundError`; `python -m pytest` passed. Importability depended on invocation method rather than project packaging. |
| 2 | Medium | `AsyncEventBus` keyed its circuit breaker side-table by `id(handler)`. `id()` reuse after garbage collection could silently attach a stale breaker state to an unrelated handler. |
| 3 | Medium | Dead-letter queue appended the same event once per failing handler rather than once per event, producing duplicate DLQ entries whenever more than one subscriber failed. |
| 4 | Low | `demo_echo`'s manifest declared no dependencies despite calling `context.authorize()`, which only works because of `security_manager` — an undeclared runtime coupling. |
| 5 | Low (accepted, not fixed) | `SecurityManager.audit()` performs synchronous file I/O from an async call path. Not fixed in this release — see rationale below. |
| 6 | Low | No `.gitignore`, `requirements.txt`, or `pyproject.toml` present in this drop. |

## Fixes Applied

1. Added `pyproject.toml` with `[tool.pytest.ini_options] pythonpath = ["."]` and setuptools packaging metadata. Removed the old `pytest.ini` (superseded). Verified: both `pytest` and `python -m pytest` now pass identically.
2. Replaced the `id(handler) -> breaker` dict with a `_Subscription` object that owns the handler and its breaker together as a single reference held in the subscriber list — eliminates the identity-reuse hazard entirely rather than working around it.
3. Reworked `_dispatch()` to track `any_handler_failed` per event and append to the dead-letter queue at most once, after all handlers for that event have run. Added a regression test (`test_dead_letter_recorded_once_per_event_not_per_handler`) so this cannot silently regress.
4. Updated `demo_echo/module.manifest.json` to declare `"dependencies": ["security_manager"]`.
6. Added `.gitignore` and `requirements.txt`.

**Public API impact: none.** `subscribe()` and `unsubscribe()` signatures are unchanged; `_Subscription` is an internal implementation detail. All 7 pre-existing tests pass unmodified; one test was added.

## Deliberately Not Fixed

**Finding #5 (synchronous audit I/O)** is accepted as known debt for this release. Making the Security Manager's audit writer non-blocking is an infrastructure-layer change (an async-safe writer, likely a small internal queue + background flush task) that overlaps directly with the Configuration Manager work about to begin in v0.2. Bundling it into a patch release risks changing security-relevant behavior under the banner of "just a review fix" — exactly the kind of scope creep the review's instructions warned against. Tracked for a future ADR once the Configuration Manager's own I/O patterns are settled, so both can be solved with one consistent approach rather than two different ones.

## Version
**v0.1.1** — patch release, review-only, no behavioral feature changes.
