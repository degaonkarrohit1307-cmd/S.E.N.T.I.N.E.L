# ADR-0001: v0.1 Kernel Foundation Decisions

**Status:** Accepted
**Date:** 2026-07-23

## Context
SAD Part 10 scopes v0.1 to: Core Engine, Event Bus, Module Registry, and
a Security Manager skeleton (scopes only, no biometrics).

## Decisions

1. **Event Bus is in-process asyncio, not a broker.** A single-machine,
   single-user workload doesn't justify Kafka/RabbitMQ operational
   overhead. Revisit only when Part 12's "multiple PCs" expansion
   requires cross-host delivery.

2. **Three fixed priority lanes (critical/high/normal), each with its
   own worker.** Chosen over a single priority-queue so a flood of
   normal-priority events can never delay a critical one behind a
   sort/poll cycle — separate queues + separate workers means true
   isolation, not just soft prioritization.

3. **Security scope enforcement ships before any biometric auth.**
   Building the `authorize()` choke point correctly now — fail-closed,
   audited, manifest-validated — means v0.7's voice/face auth only has
   to change *how* a scope gets granted, never the shape of the
   authorization call itself. No module written after v0.1 will need to
   be rewritten when auth gets richer.

4. **Fail-closed by default.** An undeclared scope AND a declared-but-
   ungranted scope both deny — verified explicitly by two separate unit
   tests, since "deny for the wrong reason" bugs are easy to introduce
   silently (e.g., accidentally treating "not yet configured" as "allow").

5. **Circuit breaker per (event_type, handler) pair**, not per module.
   A single module can subscribe to many event types; one flaky handler
   shouldn't disable the module's other, healthy subscriptions.

## Consequences
- No hot-reload yet (Part 4.5) — only one module implementation is
  registered at a time. Side-by-side versioning is deferred until v0.2+
  when there's a second real module to justify testing the swap path.
- The granted-scopes file is hand-edited JSON. This is intentionally
  primitive; a Settings UI to grant/revoke scopes arrives with the
  desktop app in v0.6, not before.
